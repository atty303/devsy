Devsy makes some of your local credentials available inside the dev container, so you do not configure them in each workspace. It supports Git credentials, GitHub CLI authentication, Docker registry credentials, and GPG keys.

<Callout type="warn" title="Only use with trusted repositories">
Code that runs in the container, including lifecycle commands and features from `devcontainer.json`, can use these credentials. Do not enable them for repositories or `devcontainer.json` files you have not reviewed.

SSH agent forwarding never exposes your private key. It does let anything in the container request signatures, and so act as you against any service the key can access, for as long as the workspace runs.
</Callout>

## Git

Devsy provides HTTPS credentials through a [git credential helper](https://git-scm.com/docs/gitcredentials). To turn off this credential injection in the default context:

```sh
devsy context set default -o SSH_INJECT_GIT_CREDENTIALS=false
```

SSH agent forwarding is separate and enabled by default (`SSH_AGENT_FORWARDING=true`). To disable it in the default context:

```sh
devsy context set default -o SSH_AGENT_FORWARDING=false
```

Disabling HTTPS credential injection does not disable SSH agent forwarding.

## GitHub CLI

With `gh` installed on the host and in the container, normal `gh` commands, aliases, and extensions can use the host's active account for each configured GitHub.com or GitHub Enterprise host. `gh` selects the target host. Explicit authentication environment variables and container-local authentication take precedence, even when invalid or expired. Account preferences in `hosts.yml` without credentials, such as dotfiles-managed `user` and `users` settings, do not prevent forwarding and are preserved.

Container logins and settings changes are saved locally. Logging out of a local account makes host authentication available again on the next invocation; it does not log out the host. Re-saving an unchanged forwarded token in the configuration file does not create independent local authentication. An explicit login saved in the container’s keyring is retained. `gh auth token` does not distinguish a missing keyring entry from an inaccessible keyring backend; forwarding can apply in either case when no file or environment credential is available. If host authentication is unavailable, `gh` runs with its normal local configuration.

To disable GitHub CLI forwarding independently of Git credentials:

```sh
devsy context set default -o SSH_INJECT_GITHUB_CREDENTIALS=false
```

The relay uses a private temporary configuration per invocation; nested commands share it. Unfinished changes are recovered on the next invocation after the previous `gh` stops, including when forwarding is unavailable.

Recent credential-free diagnostic records are kept under the user's cache directory in `devsy/gh-relay/diagnostics` (at most 64 runs). Set `DEVSY_GH_DIAGNOSTICS=false` to disable recording, or delete that diagnostics directory to remove the records. Temporary authentication and pending changes live separately in `devsy/gh-relay/session-*`; deleting those directories discards pending changes.

## Docker

Devsy provides registry credentials through a [Docker credential helper](https://docs.docker.com/engine/reference/commandline/login/#credential-helpers), so you can pull and push private images from the container. To turn it off for all workspaces:

```sh
devsy context set default -o SSH_INJECT_DOCKER_CREDENTIALS=false
```

## GPG

Devsy can forward your GPG keys into the container over the SSH tunnel, so you can sign commits there. To turn it on for all workspaces:

```sh
devsy context set default -o GPG_AGENT_FORWARDING=true
```

Or for one workspace:

```sh
devsy workspace up --ssh-gpg-forwarding my-workspace
```
